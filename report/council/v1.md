# 8. Which recommendation strategy, and why

The question is answered by walking the same two users through every method, because
the two differ in exactly the dimension that matters for a TV platform: not cold start
(both have history; the platform has none to speak of among its 1,260 test users) but
*volume of appointment evidence*. HEAVY (user 13571199046623737884) has 3,733 events over
445 distinct programmes and a candidate pool of 450. LIGHT (user 14401191285650834662)
has one event over one programme and a candidate pool of 81 — almost entirely the global
top-80. That gap in evidence, not a gap in taste, is what the six methods disagree about.

## What the two users show

| method | HEAVY (pool 450) | LIGHT (pool 81) |
| --- | ---: | ---: |
| popularity | 1/5 | 3/5 |
| association rules | 1/5 | 3/5 |
| PageRank (PPR) | 1/5 | 3/5 |
| content-based (CBF) | 1/5 | 0/5 |
| matrix factorization (iALS) | 0/5 | 0/5 |
| final — LambdaRank, 41 features | 1/5 | 3/5 |

For HEAVY, popularity, association rules and PageRank return the **identical** five
items, hitting on the same one: id 240081, "Факты. День" (Інфо). The mechanism is
appointment viewing: HEAVY's top watched items are ТСН. Неделя (538x), Завтрак з 1+1
(244x), Факты. День (222x), Сегодня. Итоги (150x), Викна-Новости (123x) — daily news
and info shows with near-uniform recurrence. With 330+ history events behind them, a
user's own co-occurrence matrix becomes dense enough that "items this user repeats" and
"items everyone repeats" converge, so co-visitation and graph diffusion (PPR's
personalised restart has little room to pull away from the stationary distribution when
the restart set already contains the global favourites) collapse onto the popularity
list. This is TV-specific: in an e-commerce basket, co-purchase structure is driven by
complementary or substitute *products*, which stays differentiated across users; in
broadcast viewing the strongest co-occurrence signal is a shared daily time slot, which
is not personal at all. CBF differs by one item (it substitutes two other Інфо
programmes, Подробности недели and Деньги, scoring genre/category/actor similarity
rather than co-viewing) but inherits the same miss pattern. iALS is the outlier at 0/5:
its latent factors pull toward "Т/с Отдел 44", "Скетч-шоу На троих", "Т/с Отчаянные
домохозяйки" — titles that reflect the catalogue's composition (88% of the 4,363
labelled programmes are category Фільми) rather than this user's appointment pattern,
which the factorization does not isolate from corpus-wide class imbalance.

For LIGHT, the single history item is a film, "Призрак" (Фільми) — and that single fact
drives every disagreement. CBF recommends four other films/series close to Призрак in
genre (Ничто не случается дважды, Агенты справедливости, Касл, Опер по вызову) and hits
nothing, because the true relevant set is the same daily Інфо programmes that dominate
most users' truth, not genre neighbours of one film. This is the opposite of what one
might expect — content attributes are supposed to help most when co-view signal is
thin — but here, with the thinnest signal in the exam set, content similarity is
actively misleading, because the one observed item is a poor proxy for broadcast habits.
iALS again misses, recommending other films (Праведник, Геракл, Призрачный патруль,
Пророк), the same corpus-composition bias as before. Popularity, association rules and
PageRank all score 3/5, but PPR's mechanism is visibly different: its personalised
restart places Призрак itself at rank 1 (a miss, surfaced because the walk is anchored
there), then diffuses to Факты. День, Викна-Новости and Сегодня. Итоги, while popularity
and association rules skip straight to the global favourites. With almost no personal
signal (pool 81, 80 of which are the global top-80), diffusion still injects one
personalised — if wrong — item at the top, while the other two simply default. That
default is correct here, the clearest instance in this exam of popularity "already
doing well": for Інфо programmes specifically, near-universal daily tune-in makes the
unpersonalised baseline a strong predictor, a pattern that would not hold for the
88%-Фільми catalogue, where taste is far more individual.

The final LambdaRank model matches the hit counts of popularity/association
rules/PageRank on both users (1/5 HEAVY, 3/5 LIGHT) but reorders them: for HEAVY it moves
the one hit from rank 2 to rank 1; for LIGHT it keeps three hits but drops a non-hit item
(Скетч-шоу На троих) in where popularity places Мир наизнанку. Because MAP@5 weights
rank, these reorderings matter even without new hits — which is consistent with the
aggregate finding that the gap between the shipped model (0.43949 ± 0.00095 on the
calibrated hold-out) and the pool's own ceiling (0.8181, identical to candidate recall)
is roughly 0.38: ranking the candidates well, not finding more of them, is where the
remaining score lives.

**Caution on "familiar vs. new."** HEAVY's hits are familiar repeats; LIGHT's hits are new
to that user's own one-item history but are not discoveries — the same near-universal
Інфо shows most active users watch, surfaced by a default, not a personalised signal.
Nothing here shows the LIGHT user *enjoyed* them, only that they were screened at ≥0.8 of
runtime. CBF's genuinely novel-looking suggestions for LIGHT (other films by genre) show
the converse: an unfamiliar recommendation is not automatically useful — it can simply be
plausible and wrong.

## Why the 41-feature LambdaRank ranker is the strategy to ship

On validation it is simply the best confirmed option: 0.43949 ± 0.00095 on the
calibrated hold-out and 0.44205 on Kaggle private (submission sub25_top5_s0), against
popularity's 0.27387, own-repeats-weighted-by-airings' 0.37324, and the frozen
leaderboard winner's 0.42912 private. Attractive alternatives were tested and rejected,
not assumed away: cascade re-ranking the top 20 cost −0.0064; adding Marrrik's
expected-frequency ("habit × schedule") feature honestly cost −0.0024, and its leaky
variant's apparent +0.0272 hold-out gain reversed to −0.011 on Kaggle private — a feature
estimating the target quantity itself flatters a hold-out and fails in production;
broadcast-history features cost −0.0013; expanding the pool by top-3 channels raised the
ceiling (0.7974 → 0.8325) but cost −0.0004, since added candidates diluted ranking more
than they added true positives. Tree/leaf sweeps (800/2400 trees, 15/63 leaves) land
within 0.0004–0.0011 of the shipped score — inside or barely outside the 0.00178
seed-to-seed noise floor, and none confirmed by submission, so they are not grounds to
switch. Ensembling lost twice: six LightGBM variants fused by rank (private
0.43419/0.43422) and a LightGBM+CatBoost fusion (0.43405) both underperform the single
ranker, because the models agree on 5.86 of 5 items on average — no diversity to fuse in
an output space this concentrated on appointment programming.

Cost favours the same choice: 1.4M rows of view log train without downsampling on a
fanless 8GB M1, one LightGBM job at a time — the GPU co-visitation pipelines and
40M-row negative-sampling schemes built for OTTO solve a sparsity problem this dataset
does not have (median history 330 events; no cold start). For the user experience, the
two examples imply a reasonable default/personalise split: a thin-history user (LIGHT)
gets a list dominated by genuinely popular, broadly-watched programmes rather than a
high-variance personalised guess, while a thick-history user (HEAVY) gets their own
recurring favourites correctly reordered.

## Limitations and failure cases

Begin with the fact that only 10.8% of schedule rows carry a `tv_show_id`: most broadcast
airtime is structurally invisible to every method here, since none can score, retrieve,
or evaluate an item never assigned an id. Within what remains addressable, 17.1% of true
answers are never in the 139-item candidate pool, and 175 of those are premieres — items
with no prior airing to generate co-occurrence, content-join, or graph signal, an
item-level cold start specific to broadcast premieres that none of the six methods can
solve by construction, distinct from the user cold start this platform does not have.
Expanding retrieval does not obviously fix this: pool 80→160 moved the hold-out by
−0.0008/+0.0014, and top-20 expansions from association rules, PageRank, CBF and iALS
added 0, 0, 4 and roughly 0 new candidates respectively — these sources are nearly
exhausted as candidate generators for this cohort. Separately, the public leaderboard
read above private for all 11 submitted models, including the frozen leader's (+0.0035
to +0.0242), so a public score cannot be read as a private one. Finally, absence of a
programme from the view log does not establish the user never watched it, only that this
platform did not record it — "never," "always," and "better" above are claims about this
log, this cohort of 1,260 test users, and this candidate pool only.
